## 결과 해석

측정 도중(2회차 Mix부터) 게이트웨이 쪽 성능이 떨어졌다. 두 도구가 같은 시점에 같은 폭으로 떨어졌고(2회차 Mix .NET 242.8 / Rust 297.3, 3회차 Put 144.7 / 143.8 ops/s), 3회차 .NET Mix의 실패 66건은 서버의 GetObject 500 응답과 응답 중단(`The response ended prematurely`)에 따른 해시 불일치(`Expected hash not equal to calculated hash` 58건)다. 같은 구간에서 Rust 실패는 0건이다. 그래서 아래 자동 요약의 3회 평균·판정은 서버 상태 변화가 섞인 값이며, 비교는 서버가 정상이던 구간으로 본다.

- Put: 처리량은 .NET과 같은 수준(0.985, ±10% 안)이고 요청당 CPU는 65%다. 최대 RSS는 .NET의 1.9배(276 MiB)다.
- Get: 처리량 1.85배, 요청당 CPU 20%, 최대 RSS 26%.
- Mix: 처리량 1.06배, 요청당 CPU 36%, 최대 RSS 79%.
- 서버 성능이 떨어진 구간(2회차 Mix, 3회차 전체)에서도 회차마다 Rust/.NET 처리량 비율은 0.99~1.22이고 Rust의 요청당 CPU는 .NET의 24~51%다.

## 자동 요약(compare.sh 출력)
- 대상: http://192.168.31.155:8383, 버킷: s3gw-rust-perf-net / s3gw-rust-perf-rs
- 클라이언트: AMD EPYC 9654 96-Core Processor, 384 코어, 메모리 376.9 GiB
- 부하: 스레드 32, 60초, 파일 크기 1M, 스레드당 파일 32개, 회차 3(회차마다 실행 순서를 바꿔 번갈아 실행)
- 처리량: 성공 건수 ÷ 설정 시간. 평균 지연: 스레드 ÷ 처리량(리틀 법칙).
- CPU 코어: (user + sys) ÷ 경과 초. CPU 사용률: CPU 코어 ÷ 장비 코어 수. CPU ms/op: (user + sys) ÷ 성공 건수.
- 메모리: 최대 RSS(VmHWM). 메모리 사용률: 최대 RSS ÷ 장비 메모리.
- 판정: 처리량·평균 지연 비율이 ±10% 안이고 실패·비정상 종료가 없으면 통과(CPU·메모리는 기록만).
